MECHANISM (new code only; no shared-line edits — D2 coordination):
  1. classify_commit_reconciliation_deltas (scraper_schema.py): candidate
     iff EVERY invariant delta is a pot/stack[N]/bet[N] field; anything
     else (current_player, cards, scraper_self_consistency, ...) drops
     byte-identically with no annotation (the seq-271 family).
  2. Gates: P1 armed; a clean REGULAR hand-start anchor for this hand-key
     (anchor_for; the regular anchor doubles as the positive
     blind-structure evidence — is_hand_start fires only when BOTH blinds
     were seen posted, so dead-SB hands can never serve one: this is what
     keeps seq-276 refusing, G3); strict chip conservation
     (Σ stack[at-start] + pot == Σ anchor); per-seat implied commits
     (anchor[i] − stack[i] − ante) all >= 0 and >= visible bet; hero and
     every live non-folded seat's implied commit EQUAL to its visible
     bet; preflop frames only (postflop derivation already implies folded
     commits from stack arithmetic — not this class).
  3. build_commit_reconciliation_shadow: a DERIVATION-ONLY copy of the
     frame with folded seats' swept bets restored to their anchor-implied
     commits. Restoring a folded blind re-enters Predicate 1's
     posted-blind detection (seq 780: the recon had mis-assigned BB=hero
     because the folded SB/BB rendered bet=null); restoring a swept limp
     re-enters the existing delayed-fold emission (seq 1086). The shadow
     feeds ONLY derive_action_sequence/replay_to_decision — never the
     invariant, the tracker, or the model.
  4. Re-validation: the UNCHANGED scraper frame goes through the same
     replay_to_decision (anchor override, no simple-model fallback) +
     check_mid_hand_invariant bar as every clean frame. The gate's two
     ante-bookkeeping HEURISTICS are replaced by the rebuild's exact
     emission knowledge (invariant.py ReconciledEmission, default-None =
     byte-identical): (a) pre-hand-convention all-in RAISES actually in
     the replayed state instead of the frame-side "any all-in seat" list
     — which over-triggers on an all-in CALL-for-less (seq 1635: seat2's
     59-chip call mis-rendered seat3's correct 175-chip lifetime as
     stack 3314/bet 125/pot 484 vs true 3289/150/509; empirically
     verified money[seat3]=3314, contrib=150 — the replayed chips were
     RIGHT and the view branch was wrong); (b) preflop
     limp-then-fold seats' ante absorption + swept bet display (never
     reachable pre-CR: the old derivation read folded preflop commits
     off the swept bet field, the exact under-count CR fixes). Every
     equality check in the gate is untouched.
  5. On success the pipeline continues on the ORIGINAL frame + rebuilt
     pack: status decision_recovered, recovered_fields labels
     "(commit_reconciliation)". The frame is never patched.

REGISTRATION DEVIATIONS (explicit)
  1. "re-validate through the UNCHANGED replay+invariant gate": the gate's
     equality checks are unchanged and the bar is not loosened anywhere,
     but recovering seq 1635 is IMPOSSIBLE through the literal pre-CR
     gate: with frame, anchor and state all fixed, the view's
     matched_all_in heuristic (contrib >= 59) deterministically
     mis-renders seat3 for ANY legal action sequence reproducing the true
     commits (proof: the replayed chips are exact — money 3314 = 3464 −
     175 + 25 ante credit — and no legal emission can avoid contrib 150
     >= 59). The fix is the flag-gated ReconciledEmission input above:
     exact emission knowledge replaces the heuristic ONLY on the CR
     re-validation path; every default caller is bit-identical (G1).
  2. "seq 1635 ... decision CHECK": the believed state recovers exactly
     as registered (pot 509, bet3 150, stack3 3289, CHECK available,
     facing_bet False) — but the POLICY, not CR, chooses the action, and
     the policy's post-floor distribution at this state is ALLIN 0.63 /
     CHECK 0.19 / raises 0.18 (sample seed 42 drew ALLIN; argmax is also
     ALLIN). The registered "CHECK" is the ground-truth/fallback action
     the operator's hand realized, not the model's choice. The unit
     fixture asserts the registered believed state + CHECK availability;
     the policy's 5hTs jam preference at 24bb is the RT-1/H1 tail-class
     concern, out of CR's scope — flagged for the arming decision.
  3. G2's "changes ONLY at recon-side invariant_fail frames" holds
     strictly in argmax mode. In sample mode the three new recoveries
     consume rng draws, so later unrelated frames' SAMPLED actions can
     shift (the known shared-rng-stream cascade D2's --mode argmax was
     added to isolate). Both modes are evidenced.
